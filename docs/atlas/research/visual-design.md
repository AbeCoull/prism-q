# Address-space figure design

The figure presents a cutaway of numerical storage, not a literal processor board.
Every visible slot represents one `f64` component in the contiguous complex128
array. Adjacent real and imaginary slots form one amplitude. Four amplitudes form
a 64-byte teaching row; the row size is an explicit cache-line model assumption,
not a detected property of every CPU.

Sage marks the lower member of the chosen amplitude pair and copper marks the upper
member. Equal slot heights encode equal storage widths, not amplitude magnitude,
probability, phase, or execution duration. The pair guide denotes a mathematical
address relation and is not a physical wire or data path. The address caption uses
the actual pair separation `16 * 2^target` bytes.

The drawing shows at most 64 amplitudes. For larger states it shows windows around
both selected addresses. Row addresses retain their true hexadecimal byte offsets,
and discontinuities are explicitly marked. The omitted space is not compressed
physical memory. Each stream can remain sequential even when its paired stream is
far away; the guide must not be read as random traversal.

The two input banks show implemented array-of-structs packing. A 256-bit AVX2 bank
contains `[re(a0), im(a0), re(a1), im(a1)]`; the paired bank contains the matching
upper-half amplitudes. A 128-bit bank holds one complex amplitude. Scalar mode
shows two scalar components without asserting a hardware SIMD register. The
selected kernel width comes from the caller's source-grounded route model and
does not follow CPU branding alone. The banks illustrate input packing, not the
entire live register set or a measured register allocation.

`MemoryScene.tsx` uses React Three Fiber for true depth and restrained orbit
interaction. Geometry consists of storage slots, row boundaries, address offsets,
and input lanes. Fine edges and four-tone materials follow the inspected Anatomy
project's isometric craft approach. No fictional connectors, board components,
or decorative state objects are introduced. Canvas textures use system monospace
fonts, so labels do not depend on remote font requests.

`AnatomyMemory.tsx` provides an interactive SVG fallback using paths generated by
the actual Anatomy `kit/iso-kit.mjs` functions `slabOf` and `iso`, at upstream commit
`1482e8469b0a9e0d8cc18ea2740a01423d29ae80`. The generated asset
`src/data/anatomy-memory-geometry.json` retains the source URL, commit, function
names, projection, and complete upstream MIT license. No upstream implementation
is copied into the runtime. Both renderers share address-window selection. SVG
amplitudes support pointer selection, Enter, Space, and focus navigation. Solid
amplitudes are drawn in projection depth order.
Regenerate the paths with `node scripts/generate-anatomy-memory.mjs` from the atlas
directory after placing the pinned Anatomy checkout at `.cache/anatomy`, or pass
the checkout directory as the first argument. Geometry generation does not download
dependencies or require a browser.

Rendering uses a demand frame loop and a device-pixel ratio capped at 1.5. No
automatic animation or time-driven effect runs. Changing selection or the manual
execution phase updates meaningful technical state; orbiting changes only the
view. Orbit damping is disabled, which also avoids unnecessary frames after an
interaction. The surrounding application supplies an accessible equivalent for
amplitude selection and handles WebGL error fallback.

The Anatomy source was inspected at its pinned checkout under the atlas cache.
The visual principles applied here are projection, purposeful part density,
restrained shading, correct depth, and model-driven state. The scientific mapping
takes precedence over introducing a mechanical metaphor. Three-dimensional
storage geometry is an educational construction; it is not a source claim about
the physical layout of DRAM, cache, or execution units.

## Preview reproduction and visual checks

Start the atlas server, then run `node scripts/capture-preview.mjs` from the atlas
directory. The optional first argument selects a server URL; the default is
`http://127.0.0.1:4173`. Playwright needs a browser and its video helper. Run
`npx playwright install chromium ffmpeg` when they are absent. Windows captures use
installed Microsoft Edge when available. If browser tools are installed under a
custom `PLAYWRIGHT_BROWSERS_PATH`, retain that environment setting during capture.

The script records a desktop overview, a 3D workspace closeup, a deterministic SVG
workspace, a 390-pixel mobile preview, and a WebM traversing the five manual
execution stages. The video shows instructional state changes, not measured
native execution or a model of wall-clock gate latency. Metadata and responsive
overflow checks are saved beside the media in `public/preview/capture-report.json`.

The final review inspected every PNG, including the SVG fallback and mobile
layout, and decoded a representative video frame. Both renderers showed no
horizontal page overflow at 1440 and 390 pixels. Reduced motion remained enabled,
and no browser page errors occurred. Storage and lane labels were enlarged after
the first review. Dense in-scene labels remain supplementary at phone size; the
DOM equations, addresses, controls and numeric state provide the readable
technical equivalent.

The compiler expansion adds a native coefficient landscape, a pass-by-pass circuit
view, and a conservative dependency DAG. Heights encode actual matrix magnitudes;
spokes encode complex phase against fixed real and imaginary directions. Zero
coefficients have zero height and no phase spoke. The matching DOM table remains
the keyboard interface and the readable numerical reference. The 3D scene has no
automatic camera motion. `node scripts/capture-expansion.mjs` reproduces the four
additional previews and saves error, renderer, typesetting, and mobile-width checks
in `public/preview/expansion-capture-report.json`.
