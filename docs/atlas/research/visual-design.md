# Address-space figure design

The figure is a cutaway of numerical storage, not a drawing of a processor board.
Each slot is one `f64` component of the contiguous complex128 array, and adjacent
real and imaginary slots form one amplitude. Four amplitudes make one 64-byte row.
That row size assumes a 64-byte cache line; it is not detected from the CPU.

Blue marks the lower member of the selected amplitude pair and red marks the
upper member. Every slot has the same height because every `f64` has the same width;
height does not encode magnitude, probability, phase or time. The pair guide links
two addresses and is not a wire or data path. The address caption gives the pair
separation, `16 * 2^target` bytes.

The drawing shows at most 64 amplitudes. For larger states it shows windows around
both selected addresses. Row addresses keep their real hexadecimal byte offsets,
and gaps are marked. Each stream can stay sequential even when its partner stream is
far away, so a long guide does not mean random access.

The two input banks show implemented array-of-structs packing. A 256-bit AVX2 bank
contains `[re(a0), im(a0), re(a1), im(a1)]`; the paired bank contains the matching
upper-half amplitudes. A 128-bit bank holds one complex amplitude. Scalar mode
shows two scalar components and no SIMD register. The kernel width comes from the
route model derived from the source, not from the CPU name alone. The banks show
input packing only, not the full register set or a measured register allocation.

`MemoryScene.tsx` uses React Three Fiber for depth and a limited orbit. The
geometry is storage slots, row boundaries, address offsets and input lanes, drawn
with thin edges and four material tones in the isometric style of the Anatomy kit.
Nothing in the scene is decorative. Canvas textures use system monospace fonts, so
labels need no remote font requests.

`AnatomyMemory.tsx` provides an interactive SVG fallback using paths generated by
the actual Anatomy `kit/iso-kit.mjs` functions `slabOf` and `iso`, at upstream commit
`1482e8469b0a9e0d8cc18ea2740a01423d29ae80`. The generated asset
`src/data/anatomy-memory-geometry.json` retains the source URL, commit, function
names, projection and the upstream MIT license. No upstream code ships in the
runtime. Both renderers share address-window selection. SVG amplitudes support
pointer selection, Enter, Space and focus navigation, and are drawn in projection
depth order.
Regenerate the paths with `node scripts/generate-anatomy-memory.mjs` from the atlas
directory after placing the pinned Anatomy checkout at `.cache/anatomy`, or pass
the checkout directory as the first argument. Generation downloads nothing and
needs no browser.

Rendering uses an on-demand frame loop and caps the device pixel ratio at 1.5.
Nothing animates on a timer. Selection and the manual execution stage change the
state shown; orbiting only moves the camera. Orbit damping is off, so no frames
render after an interaction ends. The surrounding page provides a keyboard path for
amplitude selection and falls back to SVG when WebGL fails.

The 3D storage geometry is a teaching construction. It makes no claim about the
physical layout of DRAM, caches or execution units.

## Preview reproduction and visual checks

Start the atlas server, then run `node scripts/capture-preview.mjs` from the atlas
directory. The optional first argument sets the server URL; the default is
`http://127.0.0.1:4173`. Playwright needs a browser and its video helper. Run
`npx playwright install chromium ffmpeg` when they are absent. Windows captures use
the installed Microsoft Edge when present. If browsers live under a custom
`PLAYWRIGHT_BROWSERS_PATH`, keep that variable set during capture.

The script records a desktop overview, a 3D workspace closeup, a deterministic SVG
workspace, a 390-pixel mobile preview, and a WebM that steps through the five
manual execution stages. The video pace has nothing to do with gate latency.
Metadata and overflow checks are saved next to the media in
`public/preview/capture-report.json`.

At phone width the in-scene labels are too dense to read. The DOM equations,
addresses, controls and numeric readouts carry the same information.

The compiler chapter adds a native coefficient landscape, a circuit view for each
pass, and a conservative dependency graph. Height is the matrix entry's magnitude;
the spoke gives its phase against fixed real and imaginary axes. Zero coefficients
have zero height and no spoke. The DOM table beside it is the keyboard interface
and the exact numerical reference. The camera never moves on its own.
`node scripts/capture-expansion.mjs` reproduces the four extra previews and saves
error, renderer, typesetting and mobile-width checks in
`public/preview/expansion-capture-report.json`.
